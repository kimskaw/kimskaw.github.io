grounding-verifier · security operations

AI reads the alert. Code decides.

A security alert comes in, a cheap local model reads it and proposes an action, and then code, not the model, checks every claim it made against the actual evidence before anything happens. Isolating a machine or blocking an address takes a fact that holds up, not a confident sentence.

The problem

AI is taking over first-line triage. But a model states facts with full confidence even when they are wrong, and can just as easily leave one out. If a wrong claim closes a ticket, blocks an address, or isolates a machine, that is an expensive mistake, with no one accountable for it.

What this solves

A deterministic gate that checks the AI before anything acts. Code, not a model, checks every fact against the evidence and whether a written rule allows the action, and records every decision so it can be replayed. You get to use a cheap local AI, and check it instead of trusting it.

02

Inside the gate

tri-state · fail-closed · approval-by-digest

Verify

grounding
  • Each claim is checked against the field it cites, not against the evidence in general.
  • Homoglyphs, swapped octets and flipped hashes all caught.
  • Decision-critical facts are seeded from the incident, so the model cannot supply them.

Authorize

policy
  • Does grounded evidence satisfy the action's predicate?
  • Un-evaluatable is not permitted: abstain, never pass.
  • A policy is refused at build time unless every predicate names the field its fact must come from.
  • A predicate can demand a trust tier, so isolation may only rest on the platform's own answer and never on text an attacker wrote. It can also require a second independent source.

Ledger

audit
  • Evidence + claims + verdict, hash-chained across runs.
  • Replay a hash: VERIFIED / MISMATCH / UNVERIFIABLE.
  • An unapproved policy digest forces every verdict to DENY.

no model inside the gate: a checker made of code cannot hallucinate the decision

executed comes from WasExecutingWhileDetected, a KQL enrichment scoped to this device and threat, not the model's prose. When that query returns nothing, the gate says so instead of guessing.

reputation is looked up in the same enrichment step, never by the gate, which makes no network calls. Severity says the detection was serious; it never says the address is hostile, so blocking rests on two providers agreeing. One provider alone is not corroboration and the gate abstains; a provider that disagrees, GreyNoise calling it a benign scanner, is a denial.

gate runs the policy catalogue

isolate_host no execution status in the incident ABSTAIN
block_ip remote address, reported hostile by two sources AUTHORIZE
auto_close needs severity low, incident says critical DENY
escalate_for_review no command line: wrong alert shape N/A
escalate_privesc no privilege-escalation tactic N/A

Four different answers, and they mean different things. N/A is "this policy does not cover this kind of alert"; ABSTAIN is "it does, and the evidence could not answer". Reporting those as one thing turns a routing gap into a phantom enrichment problem.

Outcome posted

Auto-isolate HELD. The enrichment could not say whether the malware ran, so the most disruptive action waits for a human. The remote address was blocked, silent close was refused, and the incident carries the label and the reasoning. Nobody had to decide the safe default at 3am.

Measured on the configuration that actually ships, with decision-critical facts seeded from the incident before the gate runs. Handing the model's raw claims straight to the gate instead gives 45.84% held and 48.95% missed; the difference is what the seeding buys. The two wrongful-action figures are not one population: 30.52% is the ungated baseline over all 4,000 incidents, 4.78% covers the 3,073 decidable incidents inside the faithful-evidence set, and corrupted evidence is the separate 16.48% to 7.62% tile.

05

Use it in your own pipeline

What it actually is

A small Python library, not a service and not a model. You keep your own pipeline. It sits at the one point where a decision gets made and answers a single question: does the evidence support this action, yes or no.

It holds no language model and opens no network connections. That is the design, not a limitation: a checker made of code cannot hallucinate the way the thing it is checking can.

  • install pip install -e . from a clone
  • needs Python 3.11 or newer
  • deps none, standard library only
  • fits anywhere you already call a model

Read that last line again

The model said the malware executed. The field it cited says it did not. Nobody wrote a rule about that specific lie, and the gate still refused: a claim that does not match the field it points at is not grounded, so the action does not run.

Note the verdict is ABSTAIN, not DENY. Those are different answers. DENY means the rule was checked and the action is not allowed. ABSTAIN means the gate could not establish a fact it needed, so it refuses to decide at all and hands the incident to a human. Nothing is automated away: an analyst gets the alert, the claim, and the field that contradicted it.

That distinction is the whole design. The gate is not asserting the host is safe, only that nothing here proves it is not. Not knowing is a real answer, and it goes to a person instead of becoming a guess.

06

What it does not do

honest scope

It moves the judgement, not removes it

Exposure shifts from the model to the evidence pipeline. A policy can now declare the trust tier a fact must come from, and require a second independent source, which halves it. What is left is a trusted field that is simply wrong, and no check inside the gate can see that.

Tamper-evident, not tamper-proof

The chain is unkeyed SHA-256. It detects an edit; a host-level attacker can recompute it. HMAC and an external anchor exist in the code and are not wired into the deployment.

The adversary is the author

Every fabrication category was written by the person who wrote the checker, on a synthetic corpus. Read the recall figures as coverage, not as an adversarial score.

A lab, not a SOC

Lab Sentinel tenant, reversible actions, one owner on change control. The abstain rate that decides whether a real SOC keeps this is unmeasured on real data.
